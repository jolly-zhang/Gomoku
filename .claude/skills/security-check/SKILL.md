# 安全审查技能

用于：扫描代码与配置，查找信息泄漏与安全隐患，输出文字报告。**只报告，不修改代码。**

## 触发输入
- 默认扫描整个项目：`src/` 全部 `.ts/.tsx`、`package.json`、`app.json`、`vercel.json`、`.gitignore`、脚本等。
- 排除 `node_modules`、`web-build`、`.expo`、`.git`、`_legacy_swift` 等产物/归档目录。
- 可选带一个目标文件/目录，只审查指定范围。

## 两类检查
**A. 信息泄漏**
- 硬编码密钥 / 令牌 / 密码 / API Key / 私钥；
- `.env` 或敏感配置被明文提交；
- 日志、报错中带出敏感内容；
- 姓名 / 邮箱 / 手机号等个人信息硬编码或外传；
- 内网地址、私密路径暴露。

**B. 安全隐患**
- 危险写法：`eval`、`new Function`、`dangerouslySetInnerHTML`、innerHTML 拼接等；
- 不安全的第三方依赖（跑 `npm audit` 查已知漏洞）；
- 敏感数据明文存储；
- 缺少输入校验、注入风险（SQL / 命令 / 路径）；
- web 配置不安全项（CORS 过宽、rewrite 泄露、静态资源误暴露）。

## 硬性约束
- 只报告，不修改任何代码。
- 仅做防御性 / 自查用途的审查；不协助攻击性、检测绕过等用途。

## 执行步骤
1. 读取目标文件与配置；跑 `npm audit` 查依赖漏洞；用 grep 扫描密钥、危险函数、网络外传等模式。
2. 逐项核对，排除误报。
3. 输出报告（固定格式，按严重程度分级）。

## 报告格式（固定）
```
安全审查报告
- 审查范围：N 个文件 + 依赖扫描
- 高危：X ｜ 中危：Y ｜ 低危：Z ｜ 提示：W
- 高危：
  - [文件:行] 问题 —— 风险说明 + 建议
- 中危：
  - …
- 低危：
  - …
- 提示：
  - …
- 结论：一段话总结整体安全状况
```

## 成功标准
- 报告按固定格式输出；
- 每个问题能定位到「文件:行」并说明风险与建议；
- 只报真实问题，不堆砌误报；对安全状况良好的项目如实说明。

# 单元测试技能

用于：为「待测代码」自动生成 vitest 单元测试 → 运行 → 给出文字测试报告。

## 触发输入
- 可选带一个目标（文件或模块路径，如 `src/core/rules.ts`）。
- 未指定目标时，默认覆盖 `src/core/` 下的全部纯逻辑模块。

## 硬性约束
- **只测纯逻辑层**：无 React / React Native / UI 依赖的 TS 模块（当前即 `src/core/`）。
- 不测 UI 组件；不新增任何测试依赖。
- **只报告，不自动修改被测代码**；发现失败只给出定位与原因，是否修复由用户另行决定。

## 执行步骤
1. **确定范围**：读目标文件，列出其导出的函数与类型；未指定则遍历 `src/core/*.ts`（排除 `__tests__`）。
2. **写测试**：在 `src/core/__tests__/<模块名>.test.ts` 新增或补充用例，遵循项目既有风格：
   - 用 vitest 的 `describe` / `it` / `expect`；
   - 覆盖正常路径、边界、异常/错误分支；
   - 禁手 / 胜负等规则逻辑，参照现有 `rules.test.ts`、`game.test.ts` 的用例补充；
   - 测试文件内用**相对路径**导入被测模块（保持 vitest 零配置可跑，不用 `@` 别名）。
3. **运行**：执行 `npm test`（即 `npx vitest run`）。
4. **报告**：按下方固定格式输出文字报告。

## 报告格式（固定）
```
测试报告
- 测试文件：N 个
- 用例总数：M ｜ 通过：X ｜ 失败：Y
- 失败用例：
  - [文件:行] 用例名 —— 失败原因（期望 / 实际）
  （无失败则写：全部通过 ✓，并列出本次覆盖的模块）
```

## 成功标准
- 测试可运行且不崩溃；
- 报告数字与 vitest 实际输出一致；
- 失败用例能指出「文件:行」与「期望 / 实际」。
